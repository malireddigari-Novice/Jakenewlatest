First identify the actual running Jakenew/Mag 7 bot and map its market-data inputs, candidate generation, order handling, fill reconciliation, persistent state and Discord sender. The ZIP contains a standalone paper/shadow reference router, not the current running bot. Its formatter does not send messages, and its router does not submit broker orders. Older JakeVolume archives and alerts_master_engine are different modules; do not assume either is the current attention engine.

Implement and compare the revised policy in paper/shadow mode on the same time-stamped observations as the existing policy. This handoff does not claim deployment, working production integrations, historical backtest results or profitable performance. The numerical thresholds below are configurable paper defaults requiring forward calibration.


1. CORE BEHAVIOR

Separate four decisions: observe flow, qualify its buy hypothesis, propose an entry, and manage each filled campaign.

Observe: Find concentrated incremental option-volume shocks with near-ask activity and surprise against comparable windows. Persistent distributed volume is background. Board rank is a watch signal, not an order.

Qualify: Only a shock occurring in the low premium band of its own exact contract contributes to buy attention or an eligible campaign cluster. Missing, middle-band and high-band value evidence contributes zero buy attention under this policy.

Enter: Require repeated, accepted, one-sided flow plus independent underlying direction confirmation, a suitable contract and all execution/risk gates. A score alone never authorizes entry.

Manage: Hold through ordinary premium noise, board changes, pauses and vague exhaustion. Request a full exit for a favorable overnight underlying gap, a planned/expiration deadline, precommitted risk invalidation, or verified opposite-side flow with underlying confirmation. Fill reconciliation is separate from the request.

Each campaign has its own ID, selected contract, horizon, risk reservation, fills and management state. Multiple campaigns can coexist. Proposing another campaign does not close an existing one.

Universe: AAPL, AMZN, GOOGL, META, MSFT, NVDA and TSLA.

Use timezone-aware timestamps. Use America/New_York for trading-day boundaries, scheduled session logic and displayed event times. Use an actual exchange calendar for holidays, session opens, early closes and expiration handling.


2. MARKET-DATA AND EVIDENCE CONTRACT

For each completed option window, retain:

- Exact contract identity, ticker, call/put right, strike and expiration; account for adjusted contracts.
- Window start and end, incremental contracts traded, print count and comparable baseline volume.
- Near-ask volume and its trade/quote classification provenance.
- Disjoint completed subwindow volume bins whose sum equals the window's incremental volume.
- Largest individual print, when available.
- Premium at window start and end, using a consistent price basis.
- Underlying spot at event time.
- Exact-contract premium percentile, reference sample count and latest reference timestamp.
- Optional implied volatility and seconds to last trading time.
- Current-session cumulative volume, when available, to locate turnover overlap.
- Complex-leg volume classification: positively simple, known mixed/complex, or unavailable.

For each full flow snapshot, retain:

- Ticker, snapshot availability time and all completed windows.
- Explicit covered expirations and call/put coverage for every covered expiration.
- Complete strike-coverage assertion and trade/quote synchronization assertion.
- Independent bullish and bearish underlying confirmation flags with their underlying evidence.
- Feed/source IDs, prior-session contract history and any earlier same-day cohort.
- The frozen OI context, if available, without accepting a replacement live chain.

For each candidate, retain:

- Stable event ID and decision time.
- Ticker, intended bullish/bearish direction, planned horizon and planned end.
- Route score, attention score, stock price and all available contract choices.
- Each contract's quote time, bid/ask, sizes, feed, expiration, strike, day volume, OI and optional externally supplied utility.
- Upstream vetoes, raw supporting evidence, evidence availability times and precommitted exit plan.
- Source campaign ID when this is an explicit rotation proposal.

For each held campaign observation, retain:

- Stable event ID, time and campaign ID.
- Current option quote, stock price and any independently confirmed structural break.
- Full current flow snapshot when available.
- Prior regular-session close, actual new regular-session opening price and opening time when evaluating an overnight gap.

Reject invalid, future, duplicate or internally inconsistent data. Reject overlapping windows for the same contract so one print cannot become multiple independent confirmations. Across successive windows, cumulative volume must advance consistently with the incremental volume. Never use cumulative day volume as a completed event-window volume.

Require genuine availability/publication timestamps. History known at the later decision time but unavailable when the event occurred must not be applied to that earlier event. Coverage and underlying-confirmation flags must reflect checks performed upstream; setting a boolean is not sufficient evidence.

Known complex legs contaminate near-ask volume, bins and print concentration. Exclude the whole mixed window until the adapter rebuilds those fields from simple trades. Do not subtract only the complex volume while keeping contaminated shape statistics. Unknown complex classification remains eligible with COMPLEX_LEG_STATUS_UNAVAILABLE logged.


3. EXACT-CONTRACT PREMIUM VALUE GATE

Compare the event premium only with earlier marks for the same exact option series: ticker, right, strike, expiration and adjustment identity.

Use at least 20 positive, valid, comparable prior marks. All reference timestamps must be strictly before the event-window start. Preserve the sample count, latest reference timestamp, reference period and observed sample range. Reject crossed, stale or excessively wide underlying quote inputs before calculating the reference.

Empirical percentile = (number of prior marks below the event premium + half the number equal to it) / number of valid prior marks.

Default classification:

- Percentile at or below 0.25: low band; eligible to contribute to buy attention and clusters if all other gates pass.
- Above 0.25 and below 0.75: middle band; zero buy-attention credit and no eligible buy-cluster contribution.
- At or above 0.75: high band; zero buy-attention credit and no eligible buy-cluster contribution. Log HIGH_VALUE_FLOW_SELL_OR_CLOSE_POSSIBLE.
- Missing percentile, fewer than 20 references or missing reference timestamp: unresolved; zero buy-attention credit and no eligible buy-cluster contribution. Log EXACT_CONTRACT_VALUE_HISTORY_MISSING.

For middle-band rejection, log PREMIUM_OUTSIDE_LOW_VALUE_BAND. Preserve rejected observations for analysis rather than deleting them.

This is a conservative operational eligibility rule. Low premium does not prove fair value or buyer opening. High premium does not prove a sale or closing trade. Log spot, IV, DTE, time of day, spread and price basis because underlying movement, volatility and decay can explain premium changes. The adapter owns comparability and quote quality.

Never use the AAPL 340C historical range to classify AAPL 345C. Never silently replace missing exact-series history with another strike or expiration.


4. CONCENTRATED SHOCK QUALIFICATION

Default requirements for an eligible shock:

- Completed window no longer than 300 seconds.
- At least 50 contracts and at least three prints.
- Incremental volume at least 2.0 times its comparable-window baseline.
- Near-ask volume at least 60% of total window volume.
- Expiration and disjoint volume-bin evidence present.
- Low-band exact-contract premium gate passed.
- No known mixed/complex-leg contamination.
- Window lies within the 1,200-second flow lookback.

Concentration must satisfy either:

A. Largest subwindow at least 45% of window volume AND largest two subwindows together at least 70%; OR
B. Largest individual print at least 35% of window volume.

A flat 20% / 20% / 20% / 20% / 20% shape is background even when total volume is very large. Log PERSISTENT_OR_DIFFUSE_BACKGROUND_EXCLUDED. Missing shape evidence is excluded with MISSING_EVENT_SHAPE_EXCLUDED.

A qualified shock with flat or falling premium can receive attention but cannot establish accepted campaign control. Log FLOW_WITHOUT_PREMIUM_ACCEPTANCE_WATCH. Accepted flow requires ending premium strictly above starting premium.

One shock remains WATCH until the independent repetition requirements below pass.


5. VERIFIED CAMPAIGN CLUSTERS

Assess calls and puts separately within each expiration. Never pool strikes across expirations to manufacture a cluster.

A campaign cluster requires either:

A. The same local pair of strikes qualifies in each of two independent, nonoverlapping completed windows; OR
B. The same strike qualifies in three independent, nonoverlapping completed windows.

The pair must form a local neighborhood: the gap between the neighboring qualifying strikes, divided by event-time spot, must be at most 2.5%. The reference implementation measures strike spacing; this is not an absolute requirement that each strike lie within 2.5% of spot. Do not impose a hard ATM-only gate on longer-dated OTM flow.

For synchronized multi-strike windows, use matching completed window boundaries. Neighboring qualifying window end times must be at most 420 seconds apart. The latest qualifying cluster window must be no more than 300 seconds old. The snapshot itself must be no more than 60 seconds old at decision time.

Require complete covered-expiration and both-right coverage plus synchronized trade/quote evidence. Incomplete, stale or future evidence cannot certify entry or rotation. Log the applicable reason, including INCOMPLETE_STRIKE_COVERAGE, INCOMPLETE_TRADE_QUOTE_OR_EXPIRY_COVERAGE or STALE_FLOW_SNAPSHOT.

Bullish entry: calls clustered, puts not clustered, and independent bullish underlying confirmation.

Bearish entry: puts clustered, calls not clustered, and independent bearish underlying confirmation.

Both sides clustered: CONTESTED. Log CONTESTED_BOTH_SIDES_CLUSTERING. Do not automatically enter or rotate from contested evidence.

Underlying direction must be derived from recorded underlying data using the actual scanner's documented confirmation rule. This package does not define that upstream rule, so preserve its feature values and provenance rather than inventing a new rule during integration.


6. ATTENTION BOARD

Rank unusual concentrated events, not gross cumulative volume. Use the strongest individual eligible event per side of each ticker. Do not add volume or attention across strikes and expirations. Use one complete snapshot per ticker per board refresh.

For each eligible event:

- Volume surprise = minimum of 1 and log base 2 of (window volume / comparable baseline) divided by 3.
- Shape = larger of largest-bin share and largest-print share.
- Recency = maximum of zero and 1 minus event age divided by 1,200 seconds.
- Without valid spot, IV and time-remaining inputs, relevance is neutral at 1.
- With those inputs, z = absolute natural log of (strike / spot), divided by IV times the square root of remaining seconds / 31,557,600.
- Relevance = 0.65 + 0.35 times exp(-0.5 times z squared).
- Raw event attention = 100 times (0.55 times surprise + 0.30 times shape + 0.15 times recency), times relevance.

The relevance weight is soft and bounded. It describes strike distance in expected-move units; it is not a fitted strike-volume bell curve or a hard rejection.

Call attention is the maximum call event score. Put attention is the maximum put event score. Ticker score is the larger of these two. Preserve two-decimal event scores and deterministic ticker tie-breaking.

Board states: WATCH, BULLISH_CONTROL, BEARISH_CONTROL and CONTESTED. Control requires verified clustering plus underlying confirmation. A high raw score or unique leader alone cannot establish control.

Maintain distinct comparable baselines for differing DTE and time-of-day conditions. Preserve the baseline methodology so it can be audited.


7. HISTORICAL TURNOVER MEMORY AND TWO SCORING SCENARIOS

For each exact contract, persist append-only observations of previous-session volume, prior reference premium, current published morning OI and, when available, the morning OI before that previous session. Retain source ID, session dates and publication timestamp.

Apply only history available by the event window. Use the window's cumulative-volume position to calculate overlap; do not flag every later window merely because the first window matched history.

With both OI observations:

Historical-match budget = smallest of previous-session volume, current morning OI, and maximum of zero or current morning OI minus earlier morning OI.

Without the earlier OI observation:

Historical-match budget = smaller of previous-session volume and current morning OI, with half-strength evidence.

For each window, its cumulative interval runs from cumulative volume minus window volume to cumulative volume. Measure the intersection of that interval with the historical-match budget running from zero to the budget. Divide overlapping contracts by window volume. Use full weight when earlier OI exists and half weight when it does not. The reference rounds resemblance to four decimals.

This yields turnover resemblance, not known closing volume and not a probability. Prior/current premium ratios do not change the resemblance score.

Example: previous volume 10,000, earlier OI zero and current morning OI 10,000 produce a 10,000-contract match budget. A first concentrated 10,000-contract window today can have full resemblance; the next 1,000 contracts are beyond that budget. A move from $1.50 to $6.50 does not prove closing, and neither does the reverse move.

For 0DTE, persist an earlier qualified same-day concentrated cohort for the exact contract: volume, reference premium, observation time and cumulative volume at its anchor. Use the earliest recorded cohort for that contract/session. A later window can match at most that cohort's volume after its cumulative-volume anchor. Apply half weight because intraday opening is unverified. Missing cohort leaves scoring unchanged. When both historical and intraday resemblance exist, use the larger value, not their sum.

Keep both scoring scenarios explicit:

A. Raw scenario: the live shock receives its full event score.
B. Discounted scenario: unmatched volume = event volume times (1 minus resemblance). Recalculate capped log surprise from unmatched volume, flooring the surprise at zero. Multiply the resulting full weighted score by (1 minus resemblance), retaining the same relevance weight.

For discounted log calculation, floor unmatched volume at one contract before taking its ratio to baseline. This avoids taking a log of zero. Retain the same shape and recency components before applying the final unmatched fraction.

Display board ordering by raw score. Persist raw and discounted call/put scores, ticker scores and ranks. Do not blend them into an uncalibrated midpoint.

scenario_leader_agrees is true only when both scenarios have the same unique positive top ticker. Ties or all-zero scores do not produce a unique leader. Log LEADER_SCENARIO_DISAGREEMENT where applicable and SIDE_SCENARIO_DISAGREEMENT when the leading side differs between scenarios.

Log OPEN_CLOSE_UNRESOLVED for positive resemblance, PRIOR_SESSION_POSITION_TURNOVER_POSSIBLE at resemblance of at least 0.75, and INTRADAY_POSITION_TURNOVER_POSSIBLE for same-day matches. These labels and evidence weights are provisional.

Turnover resemblance does not veto an otherwise verified entry. It does impose extra independent follow-through before an opposite cluster can cause a rotation exit, as described below.


8. ENTRY ROUTING, HORIZON AND CONTRACT SELECTION

Require verified one-sided accepted flow, matching independent underlying direction, a positive planned quantity, a suitable contract, no upstream veto and sufficient reserved premium capacity.

Keep the former 0.550 route-score boundary as a logged comparison. Under this shadow policy it does not veto an otherwise verified cluster. Log VERIFIED_CLUSTER_BELOW_SCORE_BOUNDARY for an accepted proposal below the old boundary. Do not remove unrelated data, execution, expiry or risk gates.

Limit new entry proposals to two per ticker per New York trading day. Count proposals, including ones subsequently cancelled, rather than only fills. Watch and strengthening messages do not count. Protective exits do not count. A rotation's new entry still counts and can be blocked by the cap.

Select INTRADAY, OVERNIGHT or SWING and a planned end before entry. The reference router does not infer the initial horizon from raw flow.

Contract eligibility:

- Calls for bullish thesis; puts for bearish thesis.
- Expiration must survive the planned end and configured horizon buffer.
- Default extra expiration buffer: one calendar day for SWING; zero for OVERNIGHT and INTRADAY. Select an actually listed suitable expiration and apply the real calendar/broker deadlines.
- If the contract expires on the planned-end date, planned end cannot exceed the configured expiration liquidation time.
- Quote cannot be future-dated or more than 30 seconds old.
- Bid must be nonnegative, ask positive, and ask must not be below bid.
- Relative spread = (ask minus bid) / bid-ask midpoint; default maximum 0.30.
- Ask size must be at least one contract.

Filter invalid choices first and journal each choice's rejection reasons. If externally supplied projected utility exists for every eligible choice, rank first by highest utility. Otherwise rank by tighter relative spread. Subsequent tie-breaks favor tighter spread, higher day volume, later expiration and stable contract-symbol ordering. Partial utility coverage must not silently outrank more liquid alternatives.

Default paper portfolio premium budget: $2,000. This is a reference configuration, not the user's account balance or an instruction to trade that amount.

Reserve proposal ask times quantity times 100 for standard contracts. Include outstanding proposal/entry quantities and active positions in used capacity. As fills arrive, reconcile the actual average fill cost and retain reservation for unfilled quantities. Do not hide a fill above the proposal ask; record it and update risk. Validate adjusted-contract multipliers in the live adapter rather than blindly applying 100 to every instrument.

Return WATCH with explicit reasons when any required gate fails. Proposals are not executions.


9. DAILY OI REFERENCE: FREEZE EXPIRATION, THEN PIN THE OPEN

The OI map is a daily location reference, independent of flow eligibility.

Before the open, ingest a complete, synchronized published OI chain with ticker, expiration, right, strike, OI, session date, publication timestamp and source ID. The adapter must actually verify completeness, both sides and relevant strike coverage.

At 9:20 a.m. New York time for a normal 9:30 regular open, freeze the latest complete chain already available and published by the cutoff. More generally use actual regular open minus ten minutes. The reference permits a job invocation from the cutoff up to, but excluding, the open; a delayed invocation still uses the original cutoff, not its invocation time.

Select the nearest listed unexpired expiration in that chain. Include the same day when listed 0DTE exists. Save the full selected-expiration chain and source provenance once per ticker/session, including an explicit empty record if data is missing. Never substitute a later expiration because it has larger OI. Never pool 0-7 DTE.

After the regular open, record the actual regular-session stock opening price, opening time, source ID and when that opening price became available. Pin it immutably for that session. Do not substitute moving live spot or a premarket price. Do not expose reference levels to a replay timestamp before the opening price was actually known.

For the selected expiration and fixed opening stock price:

- Call resistance candidates: positive-OI call strikes at or above the opening price.
- Put support candidates: positive-OI put strikes at or below the opening price.
- On each side, first take the six closest eligible positive-OI strikes by distance to the fixed open.
- From those six, select the three largest OI nodes, with distance to the open breaking OI ties and strike providing deterministic final ordering.
- Return fewer than three when fewer exist; return none when no eligible level exists.

The six-strike strip is configurable and uncalibrated. It deliberately chooses the largest nodes within a nearby eligible strip rather than the largest OI anywhere in the chain. A put above the fixed open is excluded even if its OI is enormous. A strike exactly at the open can qualify on its respective call/put side.

Persist both the OI freeze and opening-price record across restarts. Do not refresh them intraday or backfill a missed/incomplete morning chain after the open. Refresh on the next actual trading session. If the job misses the open, keep that day's OI context missing and log the incident. Missing OI must not block otherwise valid flow signals.

When enriching flow snapshots, use only the frozen OI chain. Ignore caller-supplied or subsequently published replacement OI for this reference.

Important distinction: eligibility is anchored to the fixed regular opening price. The rules do not continually recalculate the display around falling intraday spot.


10. OI CLUSTER ZONES AND SCANNER COVERAGE

Continue scanning qualifying events across all watched strikes and expirations, including strikes outside the displayed OI top three and expirations beyond the frozen nearest expiration. The OI display is not a scanner filter.

Derive a descriptive OI zone only for a confirmed flow cluster in the frozen selected expiration, using the complete relevant published chain that existed before the cluster. A farther-expiration cluster remains normally eligible but has no nearest-expiration OI zone.

Sort listed strikes on that side. Each strike's cell spans the midpoint to its previous listed neighbor and midpoint to its next listed neighbor. At a chain edge, extrapolate half the nearest spacing. Merge cells only for consecutive active strikes. Preserve lower/upper bounds, active strikes, OI per strike, expiration, right, OI publication time and supporting cluster-window times.

Return no zone for incomplete, duplicated, future or insufficient chain evidence, or when an active strike is absent. The reference needs at least two listed strikes on each side to claim complete adjacent-strike context; the adapter must still verify actual completeness beyond that minimum.

Journal the zone and full flow snapshot. Do not include diagnostic zones in the public trade card. Touching a zone, large cumulative volume at a zone, or an OI node alone cannot create an entry or exit.

OI includes outstanding long and short positions. It is not proven support/resistance and does not label a specific print as opening or closing.


11. HOLD RULES AND REMOVED EXITS

Remove premium structure broke / higher lows failed as an automatic exit predicate and position-manager input. Remove generic multi-variable exhaustion as an automatic exit unless replaced by one of the explicitly supported, auditable exits below.

Do not exit merely because:

- Premium dips, makes a lower low or loses a short-term pattern.
- The attention score drops or another ticker leads.
- The board label flips CALL/PUT without verified opposite flow.
- Ordinary flow pauses or an unquantified exhaustion label appears.
- An OI level or zone is touched.
- A gain reaches +60% or +150%, or a 35% trailing threshold is crossed.

There is no automatic half sale, percentage profit target or percentage trailing exit in this reference policy. There is also no default -18% stop. Precommitted risk controls below remain available.

If calls continue clustering and puts do not, hold the call campaign through premium noise; apply the mirror rule to puts. Both sides clustering is contested, not an automatic reversal. Existing risk and deadline exits still apply during contested flow.

Record favorable/adverse executable-bid marks, peak bids and gain percentages for later comparison. Recording a mark does not create a sale.

Retain the reference's auxiliary single-contract bar diagnostics when useful: over the last 20 completed chronological bars, record total volume, the largest three bars' share of total volume, fraction of bars with positive volume, latest bar's share, and latest close's position within the observed closing-price range. The last item is (latest close minus minimum close) / (maximum close minus minimum close), or zero for a flat range. Despite its legacy value_percentile field name, this range-location diagnostic is not the empirical exact-contract percentile in Section 3 and cannot replace that entry gate. Empty histories return zero diagnostics; future or nonchronological bars are invalid.


12. SUPPORTED FULL-EXIT REQUESTS

Evaluate the following in this priority order. Preserve all applicable reason codes.

1. Favorable overnight underlying gap.

For a position carried from before the new regular-session open, compare that actual opening stock price with the prior regular-session close. Calls exit on a favorable gap up; puts exit on a favorable gap down. The default minimum gap fraction is zero, so any strictly positive favorable gap qualifies. A flat open does not.

Request sale of all remaining contracts at the first usable opening quote. This is an underlying-gap rule, not an option-premium gap rule. Once triggered, persist the pending exit through later observations until fills resolve it. Do not assume the opening chart mark is executable.

Reason: FAVORABLE_REGULAR_SESSION_OPEN_GAP_SELL_ALL.

2. Planned or expiration deadline.

Request full liquidation at the earlier of planned end and configured expiration liquidation deadline. Reference expiration cutoff: 15:30 New York time on the expiration date. Validate the actual instrument, exchange calendar, early close and broker policy and use an earlier effective cutoff when required.

Reason: PLANNED_OR_EXPIRY_EXIT_DEADLINE.

3. Precommitted risk invalidation.

An adverse underlying level can trigger only when that level was specified beforehand and an independent structural break is confirmed: at/below the level for bullish campaigns, at/above for bearish campaigns. An explicitly configured maximum premium-loss fraction can also trigger using a fresh executable bid against actual average entry fill.

Reasons: PRECOMMITTED_UNDERLYING_INVALIDATION and/or PRECOMMITTED_PREMIUM_RISK_LIMIT.

Do not invent a loss threshold after entry. Where no earlier exit applies, the entire paid premium remains at risk.

4. Confirmed opposite-side rotation.

For a held call campaign, require one-sided accepted put clustering and independent bearish underlying confirmation; mirror for a held put. Evaluate management flow after that campaign's entry time so old pre-entry events cannot rotate it.

If both sides cluster, there is no clean rotation. If the opposite cluster includes historical/same-day turnover overlap, require later independent unmatched follow-through beyond the latest ambiguous window: either a qualifying local pair in a later window, or the same strike in two later qualifying windows no more than seven minutes apart. Those later windows must begin at or after the last ambiguous window ended and must have zero turnover resemblance. The original active-cluster requirements still apply.

Once verified, request a full exit of that specific campaign, persist the rotation direction and keep the request pending through quote problems and partial fills.

Reason: CONFIRMED_OPPOSITE_CLUSTER_ROTATION.

If follow-through is missing, hold and log ROTATION_AWAITING_INDEPENDENT_FOLLOWTHROUGH. A matched cluster can still qualify for ordinary entry; rotation uses the stricter follow-through rule.


13. EXIT REQUESTS, QUOTES AND OPPOSITE RE-ENTRY

For a usable reference exit quote, require a nonfuture bid no older than 30 seconds, positive bid and bid size of at least one. Otherwise emit EXIT_PENDING_EXECUTABLE_QUOTE and retain the exit intent. A usable quote supports an exit request; it never establishes an execution.

Implement broker-specific order routing, cancellation, fallback and reconciliation in the real integration. Prevent repeated observations from creating duplicate orders. Track fills and remaining quantity by campaign and broker order ID. Partial exit fills leave the remaining quantity open and any persistent gap/rotation intent pending.

Do not create the opposite rotation entry until the source campaign's full exit is confirmed and it is truly CLOSED. The new entry must reference that campaign, match its verified rotation direction, use still-fresh qualifying evidence and pass all entry, contract, cap and risk gates. If an entry remainder is still outstanding, the source campaign is not fully closed.

The opposite entry receives a new campaign ID and its own contract, expiration, horizon, reservation and fills. A low board score alone does not block a verified proposal. A daily cap or other failed gate still can.

Rolling to another contract is a separate executor workflow and is not implemented by the supplied reference. Broker exercise, forced liquidation and expiration outcomes must be reconciled from authoritative records, not assumed chart marks.


14. CAMPAIGN LIFECYCLE, PARTIAL FILLS AND IDEMPOTENCY

Persist at least these campaign states: PROPOSED, ACTIVE, ENTRY_PENDING, CLOSED and CANCELLED.

PROPOSED: valid proposal with premium reserved; no assumed position.

ACTIVE: actual held quantity exists. Partial entry fills increase held quantity and reduce outstanding entry quantity while preserving reservation for the remainder. Record actual weighted average fill cost and first entry time.

ENTRY_PENDING: all currently held contracts have exited but an entry remainder is still outstanding. Do not mark CLOSED and lose a later fill. Reconcile the outstanding order; if another valid fill arrives, restore held state and manage it.

CLOSED: no held contracts and no outstanding entry remainder.

CANCELLED: an unfilled proposal's cancellation is confirmed and reservation released. If an entry has partially filled, cancel only the unfilled remainder after confirmation and preserve management of held contracts.

Reference fill validation accepts entry fills only for outstanding quantity within the proposal's New York day and before planned end. The live adapter must also account for any broker event outside that expected window as a reconciliation exception rather than silently ignoring a real position.

Use stable event IDs so duplicate candidate, management, cancellation and fill events return their prior recorded result. Use transactional state changes for proposal counting and risk reservations. Restarting must preserve campaigns, pending exits, unfilled quantity, OI reference, opening spot and prior decisions.

Exit fills cannot exceed held quantity or predate entry. Record actual realized dollars from exit price minus entry basis, times contract multiplier and filled quantity. Independently recorded manual fills can be reconciled; this does not reintroduce automatic scaling rules.

16. BACKEND JOURNAL AND MEASUREMENT

Persist append-only decisions and raw supporting evidence alongside transactional campaign state. The reference uses SQLite; the existing implementation may retain its own durable equivalent if these semantics survive.

Store:

- Every candidate, including rejects and all per-contract gate failures.
- All evaluated completed windows, qualified windows and rejection reasons.
- Exact-contract premium samples/provenance and value-gate decisions.
- Coverage, quote synchronization and underlying confirmation evidence.
- Raw/discounted board scores, ranks and disagreement labels.
- Historical OI/volume memory and intraday cohorts with real availability times.
- Full OI chains, daily freeze, fixed opening price and descriptive cluster zones.
- Campaign horizon, planned end, contract selection and precommitted risk plan.
- Reservations, order IDs, actual entry/exit fills, partial quantities and cancellations.
